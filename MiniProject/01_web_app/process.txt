### 01_web_app - Process & Techniques

Overview
--------
A runnable React/TypeScript workspace for importing YouTube URLs, selecting ready
sources, asking grounded questions, and viewing analysis/research/learning outputs.
Integration follows the actual local develop@25427fe contract initially inspected
through Git. The branch was synchronized with develop before publishing the PR.

Architecture
------------
- App.tsx coordinates library, import, selection, task forms and lifecycle state.
- api.ts is the typed HTTP boundary, classified errors and sequential job observer.
- domain.ts validates supported URLs, source constraints, timestamps and terminal states.
- Results.tsx renders safe answer text, citations, coverage and typed learning content.
- sources.ts retains source generation/index identity and invalidates stale citations
  independently across answers and nested artifacts. Library refresh rechecks stored
  result jobs; a partial library page alone is never interpreted as deletion.
- demo.ts is explicitly enabled synthetic transport for development and acceptance.
- vite.config.ts loads only public API configuration and builds static assets.
- API_CONTRACT.md maps frontend operations to module 02 behavior.

Techniques and Contract
-----------------------
- Import returns per-input accepted/existing/rejected; 202 is not universal success.
- Video stage is independent of queued/running/completed/partial/failed/cancelled job state.
- Chat can return 200 or 202; analysis/research/artifacts return durable jobs.
- Polling is sequential and cancellable, stops at terminal states, and bounds transient
  read failures. A client observation timeout does not imply server task failure.
- Logical task requests freeze payload/scope and reuse Idempotency-Key on uncertain
  delivery. Once a job ID is known, retry observation instead of submitting new work.
- Preserve ready-video scope, channels and inclusive dates; never widen empty results.
- Pagination is explicit. Filters operate on loaded pages; playlist is unsupported.
- Full-analysis coverage and partial outcomes stay visible, independent of HTTP success.
- Stored artifact IDs are retrieved before displaying quizzes, cards and study plans.
- Model text is escaped; citation links are built only from validated video ID/time.
- Historical unavailable sources disable links, including sources of nested artifacts.
- Fixture headers/body modes produce a persistent visible synthetic-data notice.
- No automatic fallback to demo, provisional streaming or browser provider credentials.

Verification and Boundaries
---------------------------
Vitest checks domain/HTTP/polling behavior; Playwright checks browser flows on desktop
and mobile, state handling, escaping, scope, pagination and idempotent retries.
The optional isolated smoke runner extracts module 02 into ignored runtime storage,
uses its real HTTP/API/worker and a new fixture DB, then stops its own processes.
This validates integration mechanics without claiming live YouTube/model quality.
See TEST_REPORT.md for actual commands/results, not assumed acceptance.

No authentication, reload/session restoration, animated mascot or embedded player is
implemented. External YouTube playback and timestamp links are provided. Deployment
is outside the verified frontend runtime; delivery is tracked through Git and PR history.
