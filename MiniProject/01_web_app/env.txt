Module: Web App - YouTube Knowledge

Implemented environment
- React and TypeScript client, built with Vite; no separate frontend server is required for the static build.
- Node.js 22.12+ or Node.js 24 LTS; pnpm 11.25.0.
- Exact dependency versions in package.json and pnpm-lock.yaml.
- Vitest for domain/API checks; Playwright with installed Google Chrome for browser acceptance.
- Locally bundled Manrope and IBM Plex Sans Thai fonts; three transparent Buddy raster layers.

Public configuration
- NEXT_PUBLIC_API_BASE_URL=http://localhost:8000: Vite development proxy target by default.
- VITE_API_SAME_ORIGIN=true: relative /api in the browser; production needs a reverse proxy.
- VITE_DEMO_MODE=false: real HttpSessionPort using module-02 PR18 auth endpoints.
- VITE_DEMO_MODE=true: explicit synthetic A/B/admin account selector, never real Google auth.
- VITE_GOOGLE_CLIENT_ID: legacy/test fallback; real auth uses client_id from server challenge.
- Vite reads only NEXT_PUBLIC_API_BASE_URL from MiniProject/.env; module-local .env
  and process environment override it. Server credentials are never exposed.
- Public values are build-time settings. Restart/rebuild after changing them.
- Backend WEB_ORIGIN must exactly match the frontend origin, normally http://127.0.0.1:3000.
- Streaming remains disabled; results are rendered after the backend validates them.

Operational requirements
- Read README.md for exact installation, startup and test commands.
- Ready videos alone can be selected; explicit scope is preserved on every task.
- Poll job state separately from video stage. No invented progress percentages.
- No playlist filter is offered until the backend contract supports it.
- Render transcript/model text safely; source links are rebuilt from validated IDs/times.
- Google/model/embedding credentials remain on the server.
- Use HTTPS for deployment. Local HTTP is suitable for development.
- Fixture/demo tests do not establish live retrieval or model quality.

RAG Buddy UI integration status (2026-10-24)
- Bright CSS mint canvas replaces the forest. Layered 3D-look head/body/hand WebPs have
  original PNGs and an existing still fallback; no WebGL dependency or sensor permission.
- Default HttpSessionPort restores /api/auth/me, requests a nonce challenge and exchanges
  a transient Google credential. Session cookies and X-CSRF-Token protect mutations.
- Real admin supports server stats, member search/pagination and role/status updates only.
- Uses the existing member APIs now merged into develop. No duplicate auth client.
- See AUTH_INTEGRATION.md for same-origin deployment and outstanding release acceptance.
- Browser fixtures use ports 3001/3002/3003; identity_smoke.py also uses 3004.
- External verifier/provider fixtures do not establish real Google or live AI acceptance.
- Floating Buddy is authenticated only and shares App state/Api/conversation with full chat.
- Only ragbuddy.launcher.v1 {v,x,y} is persisted as a local UI preference. Storage failure
  falls back to the default corner; no token/conversation/history is stored there.
- Pointer/keyboard movement, visualViewport resizing and reduced motion are supported.
- Real Google popup-close/block has no fabricated detection signal; retry/help is provided.
