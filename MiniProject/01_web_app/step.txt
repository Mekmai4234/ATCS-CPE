### 01_web_app - Workflow Steps

A) Video Import and Library
---------------------------
1. The user opens the video library and pastes one or more YouTube links.
2. The frontend checks for empty input and obvious URL-format errors.
3. Send { urls[] } to POST /api/videos/import; the backend performs authoritative validation.
4. Receive jobs[] and create a card for each accepted video/job.
5. Poll GET /api/jobs/{job_id} and refresh metadata from GET /api/videos.
6. Display the real stage: queued, fetching_transcript, indexing, ready,
   no_transcript, or failed. Display a percentage only if measured progress is provided.
7. Show the thumbnail, title, channel, and an embedded-player or external-video action.
8. Enable AI source selection when a video is ready; explain unavailable transcripts or errors.

B) Questions and Follow-up
--------------------------
1. The user selects ready videos and optionally narrows channel/date/playlist filters.
2. Send { question, conversation_id, scope } to POST /api/chat.
3. Show the submitted message immediately and a loading state for the answer.
4. Receive { status, answer, citations[], coverage, conversation_id }.
5. Render the answer and source cards, or an insufficient-evidence explanation.
6. A citation click opens the original video at start_seconds or seeks the embedded player.
7. A follow-up question carries the conversation ID and current explicit source scope.

C) Research and Learning
-------------------------
1. The user enters a research goal or selects a summary, comparison, quiz, or flashcard task.
2. Submit the matching request to the API and display progress for long-running research.
3. Render the returned artifact with its citations and any partial-coverage notice.
4. Preserve the current task/input on recoverable errors so the user can retry.
