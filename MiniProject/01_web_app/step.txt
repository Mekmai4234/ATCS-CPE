### 01_web_app - Workflow Steps

A) Install, Start and Verify
---------------------------
From MiniProject/01_web_app with Node.js 22.12+ and pnpm 11.25.0:
1. pnpm install --frozen-lockfile
2. pnpm dev -> http://127.0.0.1:3000
3. Set the backend WEB_ORIGIN to the exact browser origin.
4. For explicit synthetic data only, set VITE_DEMO_MODE=true before startup.
5. pnpm typecheck; pnpm test; pnpm test:browser; pnpm build
6. Browser tests need installed Google Chrome and free ports 3001/3002.
7. For real module-02 HTTP with fixture adapters, use a Python environment containing
   its dependencies: python tests/backend_smoke.py --ref develop
8. Read README.md and TEST_REPORT.md for limits and observed verification.

B) Video Import and Library
---------------------------
1. Collect one URL per line (up to 50); preserve input while submitting/retrying.
2. POST { urls[] } to /api/videos/import. The server validates each URL.
3. Map jobs[] to input URLs by input_index; show accepted/existing/rejected separately.
4. Poll known job IDs sequentially; distinguish job state from video stage.
5. Stop on completed/partial/failed/cancelled, including completed imports whose
   stage is no_transcript. Pause with a resume action on bounded observation failures.
6. Refresh paginated /api/videos. Load further pages explicitly.
7. Show channel/date filters for loaded items; do not send unsupported playlist filters.
8. Only ready clips can be selected. Preserve explicit selection and filter constraints.
9. Deletion requires confirmation, hides the source, and observes durable cleanup.
10. Offer manual import/delete retry only for failed retryable jobs.

C) Questions and Follow-up
--------------------------
1. Validate nonempty ready video selection and nonempty channel/date intersection.
2. Freeze question, conversation_id and scope into one logical operation.
3. POST /api/chat with a fresh Idempotency-Key for that operation.
4. On 200, render the final answer. On 202, retain job_id and poll /api/jobs/{job_id}.
5. A transport retry reuses the identical payload/key; a known job resumes by GET.
6. Show insufficient_evidence, partial coverage, failure and cancellation explicitly.
7. Render citations with title/time and safe external YouTube links. Disable source
   links when sources_available=false; never trust a supplied model URL directly.
8. Store returned conversation_id for follow-ups without expanding current scope.
9. Allow cooperative cancellation of known pending tasks, observing final state.

D) Analysis, Research and Learning
----------------------------------
1. Summary/compare POST /api/analysis returns 202; comparison needs two filtered clips.
2. Research POST /api/research returns job_id/run_id. Poll jobs for state and fetch
   progress events with after_event_id; display completed/partial/failure accurately.
3. Quiz/flashcards/study_plan POST /api/learning-artifacts returns 202.
4. On completion, fetch each result.artifact_ids entry from its artifact endpoint.
5. Render typed learning content, per-item citations, source availability and coverage.
6. Show synthetic fixture mode whenever reported by response headers/body.
7. Browser memory holds current UI history; reload restoration is not implemented.
