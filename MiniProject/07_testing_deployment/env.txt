Module: Testing, Monitoring & Deployment - YouTube Knowledge

Recommended environment
- Git, the chosen Node.js runtime, and the shared Python runtime.
- Backend test tooling and browser automation after application scaffolding.
- Representative Thai/English transcript fixtures with known reference timestamps.
- Docker/Compose and CI as optional packaging/automation once runnable components exist.
- Persistent storage for application data and the vector index.
- Start with structured logs and essential metrics; larger observability stacks are optional.

Required configuration
- APP_ENV=development: distinguish local, test, and deployed environments.
- LOG_LEVEL=INFO: application diagnostic verbosity.
- DATABASE_URL and CHROMA_PERSIST_DIR: persistent data locations.
- GEMINI_API_KEY and OPENAI_API_KEY: use isolated test/deployment credentials as applicable.
- LLM_MODEL and EMBEDDING_MODEL: record exact tested/requested configurations.
- All remaining planned settings are listed in MiniProject/.env.example.

Important requirements
- Pin runtime/dependency versions before repeatable builds.
- Keep credentials and generated runtime data out of Git.
- Measure performance on a documented dataset rather than estimating it as a result.
- Preserve application data and vectors across service restarts.
- The seven work folders do not imply seven mandatory containers or network services.
- No CI workflow, deployment, or application test suite is supplied by these documents.
