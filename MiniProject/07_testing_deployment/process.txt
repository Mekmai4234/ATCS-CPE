Module 07: Process and boundaries

Inputs: existing 02-06 implementations/tests, reference fixtures and acceptance criteria.
The 07 lockfile composes dependencies without changing other manifests.
Default PR/push CI tests the merge-test/current checkout directly and publishes verified
before/after source fingerprints. Changed source is tested or provenance fails. The
integration.json workflow is now separately named and manual-only; candidate green cannot
certify current develop. Updating a pin requires lock/check/test only for that optional job.

Offline: separate suite processes -> real domain-service integration -> cold recovery ->
known-defect assertions -> lint/format -> logs/JUnit/JSON -> readiness report.
External providers are doubles; actual SQLite, Chroma and domain services are used.
Hash vectors and mock model responses cannot establish semantic quality or model access.

Deployment: package 02-06 -> resolved FullSettings snapshot -> guarded-pair initialization
-> export identical settings to API/worker -> health -> explicitly authorized live acceptance.
Test containers disable networking and mount no application data volume.

Recovery: acknowledged stopped services -> integrity/pending-job checks -> paired data
bundle -> SHA-256 verification -> new restore destination -> retrieval/source checks.
No online Chroma backup, automatic destructive rollback or overwrite is provided.

Outputs: runner, strict auth/ownership fixtures, candidate provenance, browser configuration,
reports, Docker/Caddy/Compose, active GitHub CI and operational guides. Edits remain in
07 plus the explicitly authorized root workflow. Module 01-06 production fixes belong
to their owners. Auth release stays blocked until real integration and Google smoke pass.
Browser identity acceptance uses the real HTTP adapter/API/worker with external GIS
fixtures. Production-container acceptance verifies local HTTPS, secure cookies and
unauthenticated API denial on an internal network, without release attestation or paid calls.
