### 05_ai_answers_analysis - Process & Techniques

Overview
--------
youtube_answers generates grounded answers, summaries and comparisons. It consumes
versioned evidence from 04 and returns the existing 02 AnswerResult.
02 owns conversation IDs, persistence, jobs, leases, retries and HTTP delivery.
Installation, runnable commands and full integration are documented in README.md.

Architecture
------------
- AnswerService coordinates ranked question answering and hierarchical analysis.
- RagKnowledge adapts 04 search/read/inventory/evidence using BackendExecution.
- Versioned prompts separate trusted policy from untrusted questions/history/evidence.
- GeminiModel performs one bounded async countTokens + structured generation attempt.
- GeneratedAnswer requires a source ID list for every factual statement.
- Result assembly validates citations, rechecks evidence, builds trusted timestamp URLs,
  counts processed original chunks and aggregates provider metadata.
- AnswerAdapters supplies 05 and 04 methods to 02 without changing existing factories.
- Optional TeamAdapters composes existing 03/04/05/06 and passes analyze to 06.
- Team services consume resolved backend settings without reading module dotenv files.
- The main runtime/maintenance launcher is 02's yk-full, a separate integration dependency.
- The real HTTP acceptance client imports/polls videos and produces pending human claim
  review packets with actual transcript excerpts, exact source intervals and usage/latency.

Techniques
----------
- Scoped ranked retrieval for topical questions; recent user messages help follow-ups.
- Full chunk pagination, per-video batches and recursive cited-summary reduction for analysis.
- Conservative serialized UTF-8 input guard plus live countTokens with config allowance.
- Strict output validation and per-request citation allowlists, including intermediate stages.
- Every final title/time/URL comes from source records; models cannot choose those fields.
- Evidence is re-read before returning; 02 validates again before publishing durably.
- Missing indexes produce explicit partial coverage; operational errors remain failures.

Contracts
---------
answer(request, sources, history, context) -> AnswerResult
analyze(request, sources, context) -> AnswerResult
Result: status, answer, citations[], coverage, provider_metadata.
02 adds conversation_id/job_id and handles HTTP responses/storage.
The analyze signature also matches 06's optional comparison analyzer.

Limits
------
- Reference validation proves identity/scope, not semantic support or resistance to injection.
- Processing coverage counts original chunks supplied to successful generation, including
  insufficient-evidence batches; it does not measure retained facts or understanding.
- Ranked question answering never claims complete whole-video analysis.
- Missing total inventory uses null chunk counts. Partial coverage notes are shown in text.
- No internal provider retries; 02 alone owns durable retry policy.
- Hard deadlines/context/call/chunk limits can fail a task; no resumable 05 checkpoints.
- Live generation, real-video quality and production deployment require further evaluation.
- Real semantic acceptance is never inferred from mock passes or citation identity alone.
