### 05_ai_answers_analysis - Workflow Steps

A) Grounded Question Answering
------------------------------
1. Receive { question, conversation_id, scope, history } from 02_api_backend.
2. Resolve follow-up references using relevant history while preserving explicit scope.
3. Request supporting evidence from 04_rag_knowledge.
4. If evidence is absent/inadequate, return status=insufficient_evidence with an explanation.
5. Build the prompt with a YouTube research-assistant role, grounding rules, the question,
   relevant history, and clearly labeled evidence references such as [1] and [2].
6. Check the application context budget; retrieve fewer chunks or summarize appropriate
   history if needed, and do not silently discard essential evidence.
7. Call the configured Gemini model within the time/output limits.
8. Validate the output schema and verify citation IDs against supplied evidence records.
9. Map valid references to original video titles, IDs, time bounds, and timestamp URLs.
10. Return { status, answer, citations[], coverage, conversation_id, provider_metadata } to 02.

B) Summary and Comparison
-------------------------
1. Receive the task type and explicit video scope.
2. Enumerate all eligible chunks from 04 for the requested whole-video coverage.
3. Analyze bounded batches, preserving citations and a record of processed chunks.
4. Combine batch findings into per-video summaries or a cross-video comparison.
5. Validate sources and disclose missing videos/chunks or contradictory statements.
6. Return the analysis with coverage metadata; label partial results explicitly.

C) Failures and Delivery
------------------------
1. Retry only transient provider errors within the configured time/attempt budgets.
2. If output/citations remain invalid, return a structured failure instead of invented sources.
3. Default to validated JSON. If streaming is later enabled, define provisional vs final
   events so unvalidated partial text cannot be mistaken for a checked final answer.
