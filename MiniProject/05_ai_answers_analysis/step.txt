### 05_ai_answers_analysis - Workflow Steps

Installation and runnable commands: README.md
Executed checks and limits: TEST_REPORT.md

A) Grounded Question Answering
------------------------------
1. Receive request, frozen authorized Source records, history and ExecutionContext from 02.
2. Verify the durable owner and grants. Use 02's filtered Source subset of the requested
   scope and require history/conversation to match the durable job before generation.
3. Add recent user context to the retrieval question within 04's query-byte budget.
4. Obtain actual indexed inventory and scoped ranked search hits from 04.
5. Validate each evidence video's identity/version; fit ranked evidence to the input guard
   with explicit coverage notes when low-ranked items are omitted.
6. If no hits exist, return insufficient_evidence without calling Gemini.
7. Send policy-separated evidence and question/history through the bounded Gemini adapter.
8. Validate structured output and require every statement's citation IDs in this model input.
9. Re-read processed evidence, reject changed records and map citations to trusted sources.
10. Return AnswerResult with measured partial coverage and provider metadata to 02.
    02 revalidates, stores history and adds conversation_id/job_id for delivery.

B) Summary and Comparison
-------------------------
1. Verify owner/grants and the filtered authorized scope; comparison requires at least
   two authorized videos. A research job may invoke the same analyzer through 06.
2. Enumerate all available chunks through 04 pagination, checking inventory consistency.
3. Partition each video's evidence into bounded batches and generate cited summaries.
4. Record distinct original chunks supplied to successful batch generation.
5. Recursively merge summaries, preserving citations available in each synthesis input.
6. Generate the final summary/comparison; answered analysis must cite every available video.
7. Disclose missing sources or intermediate gaps; report actual processing coverage.
8. Recheck processed evidence, assemble AnswerResult and return it to 02.

C) Failure and Lifecycle
------------------------
1. Honor context checks before/after external awaits and the remaining backend job deadline.
2. Disable SDK auto tools/retries. Classify transient transport/provider failures for 02.
3. Reject fabricated citations, invalid JSON, truncated/blocked output and source changes.
4. Fail explicitly when a chunk/context/call/time budget cannot support the operation.
5. Propagate cancellation/lease loss. No provisional answer is published as final.
6. Close generation clients, optional ingestion/Agent clients and shared RAG at shutdown.

D) Verification
---------------
1. Run locked offline unit, SDK HTTP-mock and real 02/04/06 integration tests.
2. Run Ruff lint and format checks.
3. Inspect synthetic reference cases for semantic review requirements.
4. Only when deliberately configured, run scripts/live_check.py --live --env-file PATH for
   model lookup and paid synthetic generation. Catalog access does not prove generation access.
5. Use 02's yk-full selected configuration consistently for runtime and reindex/GC.
6. Load an existing session into YK_ACCEPTANCE_SESSION, select the trusted --origin,
   complete the real acceptance plan and run yk-answers-acceptance --live against the live
   API/worker. Follow-up cases reuse conversation IDs; 200/202 are both supported.
7. Manually review every claim candidate against its transcript excerpts and original clip.
   Record semantic decisions separately from automatic structural checks and fixture results.
