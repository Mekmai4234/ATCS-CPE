04_rag_knowledge - Gemini Workflow Steps

Setup
-----
See README.md for locked install/test/Docker commands and module-local key configuration.
Initialize 02's existing schema, then run yk-rag init for additive rag04 tables.

A) Indexing
-----------
1. Receive Source, normalized TranscriptResult and ExecutionContext from the 02 worker.
2. Validate transcript hash, authorized source, current generation and execution.
3. Group caption pieces using conservative UTF-8 byte budgets and bounded overlap.
4. Preserve Unicode, segment IDs, titles and original time bounds; chunk schema is version 2.
5. Prepare title/text retrieval strings without changing original evidence text.
6. Count each final input with Gemini countTokens; reject oversized/invalid counts.
7. Embed one Content object per chunk with gemini-embedding-2 and explicit dimensions.
8. Validate one finite nonzero vector per chunk, then upsert into an invisible Chroma run.
9. Verify persisted IDs; atomically fence lease/cancellation/source and publish the manifest.
10. Clean superseded runs and return IndexReceipt; 02 verifies inventory and commits ready.

B) Retrieval
------------
0. Require the durable 02 job owner, active account and current library memberships.
1. Receive question and a nonempty subset of the current job's frozen sources.
2. Reject widened scopes, invalid limits and old/incompatible index configurations.
3. Prepare the query retrieval prefix, count it and embed with the same Gemini config.
4. Filter Chroma by exact published run IDs before cosine ranking.
5. Limit duplicates and return ranked evidence with original text and real timestamps.
6. Recheck source/run identities after asynchronous operations. 05 decides sufficiency.
7. Bind signed page cursors to account/job/source/grant/run snapshots; expire old or
   tampered cursors. Reauthorize chunk/evidence/inventory reads before returning.
8. Propagate revoked permissions as errors. Never widen empty scopes or hide denied
   access as an ordinary no-evidence answer. Admin has no private-library bypass.

C) Coverage, Replacement and Deletion
------------------------------------
1. Enumerate all chunks using snapshot-bound pages; report missing sources/unknown totals.
2. Supply exact scoped evidence lookup and actual published vector inventory to 02.
3. Keep old indexes until replacement succeeds; never combine incompatible vector spaces.
4. Hide authorized generations before deleting vectors; retain retryable failed cleanup.
5. Stop API/workers for explicit per-video reindex and abandoned-staging GC.
6. Inspect yk-rag config with the runtime profile/env files before maintenance.
7. Upgrade existing stores with init then verified bind-store while stopped.
8. Reject mismatched SQLite/Chroma identities before changing any index metadata.
9. Verify deletion before forgetting cleanup metadata; retry incomplete cleanup later.
10. Back up the application DB and whole Chroma directory, including the pair marker,
    together while stopped. Verify inventory/evidence after restoring both snapshots.
11. Membership detach revokes only that account; leave shared vectors for other users.
12. Before physical deletion, check zero refs and no other source jobs under the writer
    fence. 02's deleting tombstone must reject reimport throughout the vector operation.
13. Upgrade after 02 ownership migration, then stopped init for cursor signing state.
    Existing vector/chunk metadata remains compatible; see AUTHORIZATION.md.
14. For the full launcher use yk-full rag-init --workers-stopped with the selected
    runtime configuration; repeating full init alone does not add the cursor table.
15. Validate the actual consumer lock with the full pinned backend manifest, run
    uv sync --locked, then test the same candidate on host and in a freshly built image.
    Use the native 02/03 full-factory source contract; no separate member wrapper is enabled.
