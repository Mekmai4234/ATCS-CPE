04_rag_knowledge - Gemini Process & Techniques

Architecture
------------
Transcript -> boundary-aware chunks -> Gemini retrieval formatting -> countTokens ->
gemini-embedding-2 -> validated independent vectors -> staged Chroma -> atomic manifest.
Question -> query prefix -> countTokens -> same Gemini config -> scoped search -> evidence.
Full-video tasks enumerate every chunk for 05/06 to process and track actual coverage.

Important details
-----------------
- Gemini is the only live provider. Fixture vectors are explicit offline test data.
- Chunking uses utf8-byte-budget-v1; token_count is a labelled byte budget, not invoice tokens.
- Provider counting covers the final formatted input and prevents silent truncation.
- Count and embed requests share a deadline; cancellation propagates and SDK retries are off.
- Documents and queries have distinct retrieval prefixes included in the index fingerprint.
- One Content object per chunk prevents Gemini Embedding 2 aggregation errors.
- Original chunk text, segment links and time intervals remain intact for citations.
- Persistent Chroma is accessed through a killable subprocess; heartbeat remains responsive.
- Chunk IDs are deterministic; unique staging runs isolate attempts and invisible leftovers.
- Publication uses the existing 02 transaction-level lease guard and lifecycle checks.
- Reindex is explicit when provider/model/dimensions/format/counting/chunk schema changes.
- No distributed transaction with Chroma is claimed; offline GC removes abandoned staging.
- SQLite and the Chroma marker share a persistent pair identity; every operation checks it.
- Existing v1 databases add rag04_store_binding via init, then explicitly verify legacy IDs
  with bind-store while stopped. Wrong stores fail before manifest changes.
- Maintenance selects runtime factory profiles or explicit ordered env files. Config
  diagnostics expose resolved paths/model identity, never keys. GC needs no provider key.
- GC verifies vectors are gone before forgetting run metadata; failures remain retryable.

Interfaces
----------
Existing 02 Source/TranscriptResult/IndexReceipt/Evidence schemas remain unchanged.
RagAdapters implements index/delete/evidence/inventory; 05/06 reuse search/read_video_chunks.
Scope is a subset of the job's authorized source versions; channel/date intersection is
resolved by 02 and preserved by exact run filtering. Empty scope cannot expand to all.
Chunk schema version 2 adds an explicit counting method; rag04 table schema remains v1.

Limits
------
Ranking is not a confidence percentage; 05 decides whether evidence supports an answer.
Inventory/delivery is not proof the model processed every chunk; 05/06 track processing.
Fixture tests do not establish semantic quality; live results use a small synthetic corpus.
Transcript/title text is untrusted evidence and cannot authorize tools or change instructions.
Live ingestion, generation, research, multi-user ownership and production deployment remain
separate work. See TEST_REPORT.md for actual local/Docker/live checks.
