Module: RAG Knowledge - YouTube Knowledge

Recommended environment
- A supported Python release, ChromaDB, and an embedding-provider adapter.
- A tokenizer/chunking utility compatible with the selected embedding pipeline.
- Persistent storage for vector records and transcript/chunk metadata.
- A small evaluation dataset linking questions to known video segments.
- The existing embedding proposal is OpenAI text-embedding-3-small. Gemini is used for
  generation in 05/06; changing the embedding provider is a separate decision.

Required configuration
- EMBEDDING_PROVIDER=openai: current embedding proposal, configurable independently of Gemini.
- OPENAI_API_KEY=: server-side credential only when the OpenAI embedding adapter is selected.
- EMBEDDING_MODEL=text-embedding-3-small: existing proposed embedding model.
- CHROMA_PERSIST_DIR=./runtime/chroma: local persistent vector storage.
- CHUNK_TARGET_TOKENS=600 and CHUNK_OVERLAP_TOKENS=100: initial chunking targets.
- RETRIEVAL_TOP_K=8: initial query retrieval limit.
- These are evaluation starting points; no performance/accuracy claim has been measured.

Important requirements
- Every chunk carries video ID, title, transcript version, and actual time bounds.
- Use matching embedding models/configurations for indexing and querying.
- Apply the authorized video/channel/date scope before returning evidence.
- Keep full per-video chunk access for summaries/comparisons requiring complete coverage.
- Reindex explicitly when the embedding configuration changes; never mix incompatible vectors.
- This is a design specification. No live vector index exists yet.
