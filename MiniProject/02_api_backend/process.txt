### 02_api_backend - Process & Techniques

Overview
--------
The backend owns Google identity verification, hashed opaque sessions, CSRF enforcement,
account-scoped persistence, HTTP contracts and durable execution. Full composition connects
03-06; the smaller optional integration environment connects 04/06 with labelled offline
doubles. Source storage is shared, library membership authorizes access, and private job,
conversation and artifact owners come only from the authenticated server principal.
Worker lease/publication checks revalidate active account and authorized sources. Last-member
deletion waits for source readers and rechecks membership under the SQLite writer lock.
Explicit administrator bootstrap and paired legacy migration are documented in AUTH.md.

Architecture
------------
- main.py defines typed HTTP requests/responses, validation, CORS and correlation IDs.
- repository.py owns short transactional data operations and lifecycle decisions.
- worker.py coordinates processing, heartbeat, cancellation, deadlines and retry outcomes.
- integrations.py defines the async team contract and trusted adapter factory loading.
- runtime.py owns lazy construction, capability reporting and exactly-once async closure.
- team.py composes 04/06 with one resolved configuration; offline_model.py is a labelled double.
- schemas.py defines transcript/evidence/answer/coverage/research/learning schemas.
- database.py and frozen Alembic migrations define persistent application tables.
- fixture_adapter.py is explicitly synthetic; fixture vectors live in a dedicated test table.
- API and worker run separately with the same database and adapter configuration.

Techniques Used
---------------
- Persist-before-accept and transactional video-ID deduplication prevent lost/duplicate imports.
- Atomic claims, renewable leases and unique tokens fence stale application writers.
- Bounded retries/backoff and durable total deadlines constrain repeated processing.
- Frozen source generations/versions and checks before publication prevent source drift.
- Async adapters must honor cancellation; 04 must fence independent vector-store publication.
- Final citation identity and overall transcript bounds are checked; URLs are constructed
  from trusted video IDs/times. Semantic claim support still requires evaluation by 05/07.
- Complete-coverage claims require known matching counts and actual index inventory.
- Conversation user turns survive generation failure; successful assistant/citations/job
  results commit atomically. Follow-up history never widens the selected source versions.
- Idempotency keys avoid repeated AI work after network retries.
- Request/job/run IDs correlate logs without dumping credentials or conversation bodies.

Contracts
---------
See ../docs/backend_api_contract.md and the generated /docs and /openapi.json.
Analysis, research, artifacts and deletion use durable 202 acceptance plus polling.
Chat normally returns final JSON; pending/retrying chat also returns a job ID with 202.
The default unavailable mode is honest about missing integrations; fixture mode labels
synthetic output and never calls paid providers. A trusted custom factory connects 03-06.

Current limitations
-------------------
Single-user local prototype; no authentication, playlist/channel discovery, scheduler,
speech-to-text fallback, streaming or production deployment. Channel/date filtering uses
available metadata and never silently ignores unsupported playlist scope.
Research interruption cannot resume without a module 06 checkpoint contract; events remain,
and a hard timeout is failed unless a valid partial result was returned before the deadline.
Deletion preserves saved history/artifacts and minimal lifecycle audit, not all past source text.
Live provider compatibility, answer quality and production backup/load evaluation remain open.

Current integration delivery
----------------------------
See integration/README.md and INTEGRATION_TEST_REPORT.md. Optional dependencies/lockfile,
Docker runtime/test targets and Compose are owned entirely by module 02. The root shared
templates and modules 04/06 are not edited. Jobs additionally retain a custom factory/profile
identity, so an offline database cannot silently become live. Historical custom databases
without this identity require explicit migration planning rather than automatic relabelling.
Static missing capabilities fail before a request creates a doomed job. Health does not call
paid providers. Hard total timeouts stop auto-retry even at timer/wall-clock rounding boundaries;
per-call chat timeouts can retry while a total budget remains.

Full-system configuration and deployment
----------------------------------------
The 02-owned yk-full entrypoint exports every resolved 02/03/04/05/06 setting to
child processes, overriding module-local dotenv files without editing modules.
The existing 05 team factory owns service composition. An additive 02 SQLite table
and a Chroma-directory marker bind fresh stores to one profile/factory/fingerprint.
Explicit init and startup/maintenance checks do not rebind or migrate legacy data.
The full Docker image is separate from the 04/06-only integration image.
See full/README.md and FULL_TEST_REPORT.md for deployment and verification limits.
