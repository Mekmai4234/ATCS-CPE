### 02_api_backend - Process & Techniques (README)

Overview
--------
The backend is the gateway between the web app and the ingestion/AI modules. It owns
application persistence, request validation, import scheduling, conversation history, and
delivery of results. This document specifies intended behavior, not a running service.

Architecture
------------
- Router layer defines HTTP endpoints and validates input/output schemas.
- Service layer coordinates imports, questions, analysis, and research runs.
- Repository layer reads/writes application data through parameterized database operations.
- A persistent worker processes ingestion/indexing jobs outside the HTTP request lifetime.
- Modules 03-06 may be Python packages in the same deployment; separate network services
  are optional, not required by the numbered work folders.

Techniques Used
---------------
- Persistent jobs and idempotency prevent lost work and duplicate imports.
- Short import requests return job IDs while workers perform slow processing.
- Worker claims, bounded retries, and restart recovery protect processing consistency.
- Request IDs connect API events with worker and model telemetry.
- Durable history storage preserves answers and citations for follow-up questions.
- Optional authentication must enforce ownership before retrieval, not only after generation.

Data Schema and Interfaces
--------------------------
- Video: video_id, canonical_url, title, channel_id, published_at, import status.
- TranscriptSegment: segment_id, video_id, text, start_seconds, duration_seconds,
  language, transcript_version.
- Job: job_id, video_id, stage, attempt_count, error_code, retryable, timestamps.
- Conversation/Message: IDs, role, content, citations, scope, timestamps.
- LearningArtifact/ResearchRun: IDs, task/type, scope, state, content, citations, coverage.
- See docs/architecture.md for proposed HTTP endpoints and shared field conventions.

Design Rationale
----------------
The API owns persistent state while 03-06 own their processing responsibilities. This
separation allows UI and AI development to proceed against agreed contracts.

Things to Watch Out For
----------------------
- In-memory background tasks alone do not provide the required restart recovery.
- ready means transcript indexing succeeded, not merely that a title/thumbnail was fetched.
- no_transcript is different from a network failure or provider restriction.
- Handle deletion during processing so a late worker cannot recreate deleted knowledge.
- Do not log provider keys, full credentials, or unnecessary conversation content.
