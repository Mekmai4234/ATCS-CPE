Module: API / Backend - YouTube Knowledge

Implemented environment
- Python >=3.11,<3.14; verified on Python 3.11.16 on Windows.
- FastAPI, Uvicorn, Pydantic Settings, SQLAlchemy 2.0 and Alembic.
- File-backed SQLite with foreign keys, WAL, busy timeout and short BEGIN IMMEDIATE writes.
- Separately running asyncio worker; no in-memory-only background job queue.
- uv.lock pins tested dependencies. pytest, pytest-asyncio, HTTPX/HTTPX2 and Ruff are dev tools.
- Run instructions and demo requests: 02_api_backend/README.md.

Configuration
- API_HOST=127.0.0.1; API_PORT=8000; WEB_ORIGIN=http://localhost:3000.
- DATABASE_URL=sqlite:///./runtime/app.db; paths resolve from the MiniProject root.
- ADAPTER_MODE=unavailable by default. fixture enables labelled offline fixtures only.
- ADAPTER_MODE=custom requires ADAPTER_FACTORY=package.module:create_adapters.
- JOB_MAX_ATTEMPTS=3; JOB_LEASE_SECONDS=30; JOB_TIMEOUT_SECONDS=180.
- JOB_RETRY_BASE_SECONDS=2; WORKER_POLL_SECONDS=1; IMPORT_MAX_URLS=50.
- ENABLE_STREAMING=false; true is rejected until streaming semantics are implemented.
- GEMINI_API_KEY and LLM_MODEL are passed as server configuration for future 05/06 adapters.
- OPENAI_API_KEY/EMBEDDING_MODEL remain separate module 04 configuration.
- Research uses AGENT_TIMEOUT_SECONDS=120 and AGENT_MAX_STEPS=8.

Boundaries
- Default mode never fabricates integrations; missing adapters produce classified failures.
- Fixtures require APP_ENV=development or test; no external or paid requests are made.
- Module 02 does not implement ingestion, Chroma search, Gemini generation or an agent loop.
- Credentials remain server-side and are never included in HTTP responses or raw logs.
- This release is single-user. Authentication/multi-user authorization is a later feature.

Docker environment
- Dockerfile provides non-root runtime and Linux test targets using the same uv.lock.
- Root compose.yaml runs migrate, api and worker with a persistent named volume.
- The test service and compose.test.yaml force isolated offline fixture scenarios.
- scripts/docker_smoke.py runs container verification and cleans its unique test project.
- README.md contains Compose startup, test, port and persistence instructions.
