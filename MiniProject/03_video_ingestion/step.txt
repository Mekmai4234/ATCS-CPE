03_video_ingestion - Workflow Steps

A) Setup
1. Follow README.md to install the locked 03 environment and configure server-side values.
2. Initialize existing 02 schema and additive 04 manifest explicitly.
3. Start API/worker with the same 03-owned live factory, database and index configuration.

B) Ingestion
1. 02 validates URLs, deduplicates IDs and persists per-video jobs.
2. The worker calls ingest(video_id, context); 03 checks ID, ownership and remaining time.
3. Fetch metadata within a short budget; retain null metadata on classified failure.
4. Start a caption SDK subprocess. Select configured language first, then manual before
   generated captions in that language. Do not translate or synthesize captions.
5. Monitor ownership/cancellation. Timeout/cancellation kills and reaps the child.
6. Validate data, preserve Unicode/timing/overlaps, sort by start and normalize whitespace.
7. Assign stable unique segment IDs; reject invalid intervals or mismatched video IDs.
8. Return strict TranscriptResult with metadata/language/source/segments to 02.
9. 02 stores transcript and computes version, calls 04 to index and verifies inventory.
10. 02 publishes ready only after success. 03 never performs a duplicate index call.

C) Errors
1. No preferred usable captions: no_transcript, non-retryable.
2. Unavailable/restricted video or IP/access block: distinct non-retryable code.
3. Timeout/network/HTTP 429/5xx: classified retryable error; 02 owns bounded retry.
4. Invalid output: explicit non-retryable failure without raw provider exception text.
5. Metadata failure does not erase captions; missing channel/date never bypasses filters.

D) Verification
1. Run offline unit, SDK HTTP, subprocess and API/worker/real-Chroma checks.
2. Run explicit live_check.py for a public video when live verification is needed.
3. Record contacted providers and limitations in TEST_REPORT.md.

Future: channel/playlist discovery, ready-video refresh, scheduling and optional ASR.
