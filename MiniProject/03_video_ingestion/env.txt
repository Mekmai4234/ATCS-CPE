Module: Video Ingestion - YouTube Knowledge

Implemented environment
- Python >=3.11,<3.14; package youtube_ingestion; dependencies pinned in uv.lock.
- youtube-transcript-api with a bounded requests Session in a killable subprocess.
- HTTPX async public oEmbed / optional YouTube Data API metadata.
- Existing 02 schemas, jobs and persistence; existing 04 RAG implementation.
- pytest/pytest-asyncio/Ruff; real temporary SQLite and persistent Chroma in integration tests.
- Installation/start/test commands are in README.md.

Configuration
- TRANSCRIPT_LANGUAGES=th,en: language priority, then manual before generated per language.
- INGEST_TIMEOUT_SECONDS=30: entire attempt, bounded by remaining backend job time.
- METADATA_TIMEOUT_SECONDS=5: also capped at one quarter of the ingestion budget.
- METADATA_PROVIDER=auto: Data API with configured key, otherwise oEmbed; none disables metadata.
- YOUTUBE_API_KEY=: optional server-side metadata key; never saved in source or request URLs.
- ENABLE_TRANSCRIPTION_FALLBACK=false: true rejected; fresh ASR is not implemented.
- The 03-owned live factory also needs 04's GEMINI_API_KEY and Gemini embedding configuration.
- Configure Backend DATABASE_URL and ADAPTER_* separately as documented in README.md.

Boundaries
- 02 owns URL normalization, dedup, database writes, transcript hashes/versions and retries.
- 03 returns TranscriptResult; 02 alone calls 04 and publishes ready status.
- Keep original time intervals, language and manual/generated provenance.
- Metadata failure retains captions with null metadata and a separate classified warning.
- No translation, paid transcription, authenticated YouTube captions, discovery or scheduler.
- Offline tests use network/embedding doubles. The separate live check reads public YouTube only.

Native member integration (requires 02 PR18 and 04 PR20)
- Use AUTH_ENABLED=true and the native 02 session/CSRF and ownership contract.
- The optional member_adapters:create_member_adapters name delegates to the same native
  ingestion/RAG composition; no member_ingestion_backend or SourceGrant is installed.
- Import batch limits use 02's IMPORT_MAX_URLS. Durable per-member pending/running quotas
  and fair claims are not implemented by 03; removed MEMBER_* values do not enforce them.
- Google/session/CSRF/origin/cookie configuration belongs to 02, not 03/.env.
- Acceptance requires explicit --fixture-identity --fixture-embeddings in a new test DB.
- See MEMBER_CONTRACT.md and MEMBER_REPORT.md for exact tested dependencies and gaps.
